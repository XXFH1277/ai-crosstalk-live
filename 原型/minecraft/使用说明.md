# Minecraft 接入台

这是独立的双人游戏导演台，端口 7861。深深和月月分别进入世界，共用对话和配音队列；任务执行器独立行动，聊天不能覆盖任务。开启网页声音会调用现有模型接口及 Breeze F16；纯游戏文字模式只调用模型。原来的 7860 相声导演未作改动。

## 启动

在此目录执行 `npm start`，打开 http://127.0.0.1:7861/ 。Node.js 需要 22 或以上，依赖版本已锁定在 package-lock.json。

1. 在 PCL 启动 Minecraft Java 1.21.6，进入测试世界。
2. 按 Esc → 对局域网开放，启动局域网世界，记下显示的端口。
3. 在接入台填端口，点击“两人入服”。游戏里的名字是 ShenshenBot（深深）、YueyueBot（月月）。
4. 等待“短音已就绪”，点击“开启声音和 AI”。浏览器第一次需要这个点击来允许声音播放。关闭播放页面后，AI 最迟约 15 秒自动暂停，避免无人播放却持续调用模型。
5. 首次先缓冲两句，之后边播放边准备后续台词；页面显示已备好的句数。慢接口导致第二句长时间未就绪时，20 秒后允许先播第一句。缓冲只能减少空挡，生成长期慢于播放时仍会等待。
6. “暂停 AI 并停止动作”会取消生成、清掉缓存并停止两人动作。单独点任一角色“跟随”也会暂停 AI，改为手动控制。
7. 死亡后点对应角色“重生”。结束时点“两人离开”；终端 Ctrl+C 关闭接入程序。

本版本只连接 127.0.0.1 上的原版世界，bot 使用本地离线身份；尚未提供正版服务器的独立 bot 账号登录。如果当前世界拒绝该身份，需要另外配置独立 bot 账号或专用本地测试服务器，不会读取、复制或复用 PCL 的登录凭据。

## 游戏聊天和文字指挥

当前指挥玩家是 **YourMCName**。游戏里按 **T** 输入，或者在网页“一起做什么”输入。两只 bot 收到同一聊天只处理一次，不会把自身回复当作指令。

| 输入示例 | 行为 |
| --- | --- |
| 月月，你现在在干嘛？ | 月月先回答，搭档可以简短接话；不替换当前任务 |
| 两人跟着我 | 两人持续跟随指挥玩家 |
| 深深跟着我 | 只安排深深跟随 |
| 两人制作工具 | 按生存配方制作工作台、木镐，采圆石升级石镐和石剑；需要附近可达的原木和石头 |
| 两人砍树 4 块 | 各分配两块新增原木，以背包增加数量确认 |
| 月月挖矿 2 块 | 查找附近可达的石头/矿物；需要相应镐 |
| 两人打怪 | 两人都参与处理附近敌对生物；需要斧/剑和至少 12 点血，不攻击玩家 |
| 自由玩 | 自主采少量原木，然后会合、检查资源并继续小目标 |
| 停止 / 停止挖矿 / 不要打怪 | 停止两人的任务、移动与生成 |
| 月月停止 | 只取消月月任务，深深继续原任务 |

数量用阿拉伯数字，一次 1～16；当前识别以上短指令，不执行任意代码、游戏斜杠命令或复杂复合任务。“你在砍树吗？”是聊天，不会误开砍树。采集任务按角色分配配额，不会把对方捡到的物品记进自己的完成数。

两人已入服时，直接从游戏聊天发消息即可开启纯文字模式；回复出现在游戏聊天栏，不要求浏览器保持播放。网页点“开启声音和 AI”可切到配音模式，游戏里发起的聊天仍会收到文字回复。网页声音模式关闭页面后约 15 秒暂停；纯游戏模式在指挥玩家离开可见玩家列表后也会暂停。

失败/完成结果直接反馈游戏聊天和任务栏。找不到目标、路径受阻或目标消失会换目标或有界重试；单次动作约 12 秒、采集任务约 90 秒、制作工具任务约 240 秒上限。缺工具会立即说明条件，不假装开工。重新下令可从失败状态恢复。手动停止后迟到的动作结果不能重新启动旧任务。

## 已有能力与边界

- 两人读取各自位置、血量、饥饿值、可见玩家、附近实体和背包，根据真实状态选择有限动作。
- 小事有收尾：开场最多四句，新背包或任务结果通常最多两句，普通交流 30 秒最多准备四句；玩家主动说话可优先接两句。执行中的任务约 25 秒开放一次自然交流，围绕目标、现场和下一步，不周期翻炒已完成/失败的旧任务。动作由独立执行器推进，不等生成或配音。
- 观察、看向搭档不会停止正在执行的任务；挖掘和短距离行走执行期间，暂不接受模型切换到另一项动作。手动暂停、受伤避险和断连仍可立即停止。普通背包/任务变化清掉未播缓存，当前已经播放的句子可以说完。
- 自主模式以小目标循环：先采原木、再与玩家会合，条件允许时补充资源；可通过“制作工具”单独安排基础工具制作；不会自动建房或通关。查找范围最多 24 格，落脚点核验地面、空间和方块视线，再交给寻路器。寻路不会主动挖路、搭桥或跑酷。
- 模型不执行任意代码或游戏命令。动作在台词实际播放前重新检查；不合法或状态已变化就清掉旧缓存。接话上下文包含按顺序排好的待播句，但只有实际播放完成的句子进入已说历史。
- 掉血立即显示对应角色惊讶表情、抖动并播放缓存短音，不等模型或 TTS。两人各有两种普通受击短音、低血量、死亡和恢复短音，总计 10 条。连续普通掉血按既有规则限频，伤情变化会取消旧台词。
- “试听受击声音”交替试听深深和月月，不改变游戏血量。立绘表情作用于网页，不会改变游戏人物的像素皮肤；反应脸不叠嘴型贴片。
- 低血量停止动作；尚无自动避险或吃饭。受控打怪仅在明确指令和装备/血量条件满足时运行，未完成完整战斗实测，不保证角色不受伤或死亡。
- 输出经过现有违禁词及泄露检查，中转暂时失败时尝试现有备用模型；不修改现有 API 配置，也不把密钥发给页面。
- 按用户要求，游戏聊天入口会接收指挥玩家消息并由 bot 发出回复/任务反馈；语音模式同时使用各自的 Breeze 音色。未接入抖音弹幕。
- 此页面使用浏览器当前输出设备；若要直播采集，仍需核对浏览器的声音输出与直播伴侣设置。

## 音频与调试

首次启动会用现有角色音色生成短音，保存在 `原型/runtime/minecraft-audio/`；之后直接读取，不因受击重新合成。必须先启动 Breeze F16；音频准备失败会显示提示，修复服务后重启本接入台。

有状态、没有声音时，先点击“试听受击声音”。如果正在另一个页面播放，先点暂停，再从当前页面开启；同一时刻仅一个页面拥有 AI 对话播放权。启动、配音、反应和模型失败状态均在页面显示。台词音频仅保留最近 24 条在内存中。

## 离线检查

在 `原型` 目录执行 `node tools/check-minecraft-bridge.mjs`、`node tools/check-minecraft-reactions.mjs`、`node tools/check-minecraft-ai.mjs`、`node tools/check-minecraft-pacing.mjs`、`node tools/check-minecraft-tasks.mjs`。均使用模拟事件，不连接游戏、真实模型或 TTS。覆盖消息去重、停止优先/疑问不执行、分工配额、背包计数、缺工具、目标消失、取消迟到结果、不可达目标切换、纯文字回复及任务中恢复交流。
