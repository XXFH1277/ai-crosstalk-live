## 推荐环境

- 第一阶段：Minecraft Java 版 1.21.6 原版，Java 21（64 位）。PCL 下载页选“正式版”中的 1.21.6。它是 Mindcraft 当前 README 推荐的版本；以原版先验证连接和行动。

- 后续若画面性能不足，再考虑匹配 1.21.6 的 Fabric 与 Sodium；先不上光影和大型玩法整合包。
- 第一阶段可用单人世界开放局域网；账号认证方式与 bot 登录需在接入时核对。长期直播再配置固定端口的专用本地服务器。
- PCL 负责启动拍摄用游戏客户端；bot 独立运行，不需要每个角色都开一个游戏画面。

## 两种速度

即时反应走本地规则、预载短音和表情，不请求模型或 TTS。受伤时先有反应，后台同时准备有上下文的后续台词。目标是事件到达后尽快响应，实际延迟仍需联调测量，短音只能遮住部分等待。

| 情况 | 本地规则 | 后续模型任务 |
| --- | --- | --- |
| 掉血 | 受伤短音和表情；同角色普通短音至少间隔 2.5 秒 | 结合已知环境决定下一步，搭档可接话 |
| 血量 ≤6（3 颗心） | 升级为危险反应，不受普通短音冷却限制；输出避险意图 | 改写过时的采集、探索计划 |
| 血量为 0 | 死亡反应一次；输出停止意图 | 根据真实已知情况吐槽，不能编造凶手 |
| 血量 ≥10 且至少 4 秒未掉血 | 解除低血量状态、短暂松口气；并不保证环境已安全 | 再规划接下来的行动 |
| 新伤情、重生或反应过期 | 原有反应对应的生成结果作废 | 重新根据最新状态组织台词 |

血量使用原版 0～20 数值；同血量重复上报不反复触发。接入层需要定期调用 observeHealth（例如每 250 毫秒），以便没有新掉血事件时也能判断恢复；重生、重连时先 reset。只有自己的 bot 才能进入判定，不能把所有实体受伤都归到角色身上。血量减少只能证明掉血，不能直接认定是某玩家打的。

模块输出 safety 只是意图，不会自动逃跑。后续行动执行器必须结合已加载地形、危险来源和可达路径执行；停止当前任务后不能盲目后退进岩浆。

## 接导演和画面时的要求

1. 游戏模式增加独立事件类型，不把受伤冒充弹幕或礼物。相声模式与现有礼物优先、审核、去重规则保持兼容。
2. 即时反应和正文音频分开管理。普通受击优先显示表情；同一角色正在说话时避免两个人声重叠。本版游戏伤情会中断过时的游戏话语，必要时取消后续游戏台词，不能误清谢礼物队列。
3. 接入方用 reaction 的 revision 和 expiresAt 在写词完成、配音前、播放前检查 isCurrent；重生重连使旧台词失效。聊天历史记录实际说出的内容，不能把被取消的句子记成已说完。
4. 一次短音结束不代表正文结束；正文的 `/api/played` 确认仍按真实正文播放处理，避免打乱导演队列。
5. 表情先映射直播立绘。游戏人物本身的表情属于另一项能力，不会因为网页表情改变而自动改变 Minecraft 皮肤。
6. 受伤、惊讶、喘气等短音按角色准备多个版本，提前加载并避免连续重复。现有垫场词不能直接当成受伤录音。生成时用 Breeze F16，并沿用短音去杂音与淡出处理。
7. 反应类立绘若脸型已变化，禁止叠口型贴片。音频缺失时只做表情，不能临时等待 TTS 或播放不相干的旧录音。
