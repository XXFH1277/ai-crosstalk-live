# Breeze TTS 2 · Apple Silicon 中文部署测试包

此包为 M1 Max / 64 GB Mac 准备，目标为 Apple Silicon、macOS 14 或更新版本。它会在你的 Mac 上编译原生运行程序，尝试 Metal 加速，并准备 CPU 备用版本。

**此包尚未在真实 Mac 上完成编译和语音验收。** 已在 Windows 制作、核对资源并检查脚本/控制逻辑；Mac 的实际编译、Metal 算子支持、音频效果和运行速度需要你拿到机器后测试。不能将 Windows 上的测速当作 M1 Max 的速度。

## 第一次使用

1. 完整解压到有写入权限的目录，例如 `~/Documents/Breeze TTS 2`。不要直接在 ZIP 内运行，保留整个目录结构。中文和空格路径已按脚本要求处理。建议放在本机 APFS 磁盘，预留至少 **30 GB** 空间供 ZIP、模型和本机编译缓存使用。
2. 双击 **一键部署.command**（英文同入口为 `Deploy-Breeze.command`）。脚本核对 SHA256，解出包内 Python/CMake，再编译 Metal 与 CPU 后端。初次编译需要等待，完整输出保存在 `logs/deploy-*.log`。
3. 如果缺少 **Apple Xcode Command Line Tools**，部署脚本会请求打开 Apple 官方安装提示。请在系统窗口完成安装，再重新双击部署入口。也可单独双击 `Install-Apple-Tools.command`，或在终端运行 `xcode-select --install`。这一步需要 Apple 下载服务；Apple SDK 和编译器不能作为通用第三方安装包随包分发。已有有效工具和 SDK 时，部署无需联网，也不需要 Homebrew。
4. 部署默认用 **Q8 + Metal** 启动，成功后打开中文网页 `http://127.0.0.1:8080/`。第一次 Metal 启动会现场编译着色器，需要额外等待。脚本先构建 CPU，再尝试 Metal；若 Metal 编译失败而 CPU 编译成功，会明确提示使用 CPU；若 Metal 编译成功但运行失败，可双击 `Start-CPU.command` 测试备用版本。要完全跳过 Metal 构建，可使用 `Deploy-CPU.command`。
5. 初次启动成功后，双击 **Self-Test.command**。它会使用保存的声音生成两份中文 WAV，验证 F16/Q8 切换，并恢复测试前的模型。试听文件为 `outputs/mac-self-test-q8.wav` 与 `outputs/mac-self-test-f16.wav`；报告为 `logs/mac-self-test.json`，诊断为 `logs/diagnostics.json`。若失败，把相应日志带回此聊天排查。

首次需要从系统安全提示中确认文件来源时，请使用 macOS 正常的打开流程。脚本不会关闭 Gatekeeper，也不会清除隔离标记。如果提示“没有访问权限”，可以在终端执行 `/bin/bash `（末尾留一个空格），把 `一键部署.command` 拖到终端中再按回车；此方式也适用于解压工具没有保留执行权限的情况。若文件被系统明确判定损坏或拦截，请先保留提示与日志排查，不要关闭系统保护。

## 日常入口

| 入口 | 作用 |
| --- | --- |
| `Start-Breeze.command` | 使用上次保存的模型和后端启动 |
| `Start-F16.command` | 使用 F16，保留当前 Metal/CPU 后端选择 |
| `Start-Q8.command` | 使用 Q8，保留当前 Metal/CPU 后端选择 |
| `Start-Metal.command` | 尝试 Metal，保留当前模型 |
| `Start-CPU.command` | 启动 Q8 + CPU 备用模式；通常会慢很多 |
| `Deploy-CPU.command` | 只编译并启动 CPU 版本，用于排查 Metal 构建问题 |
| `Install-Apple-Tools.command` | 请求打开 Apple 官方编译工具安装提示 |
| `Stop-Breeze.command` | 停止本目录的 UI 和模型服务，释放内存 |
| `Check-Mac.command` | 校验文件和编译环境，准备离线工具但不编译/启动模型 |
| `Self-Test.command` | 真机双模型中文生成与切换测试 |
| `Diagnose.command` | 保存运行环境和服务诊断信息 |

网页顶部可以选择 **F16 / Q8_0**，再点击“切换模型”。加载完成后再生成语音。生成或处理参考声音时切换按钮会锁定；已保存的声音选择和文本在切换后保留。模型切换保持当前的 Metal/CPU 后端，需要更换后端时使用对应 `.command` 入口。

关闭网页不会停止后台模型；用完可双击 `Stop-Breeze.command`。如果端口 8080/8081/8082 被其他程序占用，请先停止对应程序或另一个 Breeze 副本；本包不会为了占用端口而结束无关进程。

## 模型、中文界面和声音库

- 已包含 F16（约 6.28 GB）和 Q8_0（约 3.57 GB），保留原有 GGUF，不用重新下载模型。一次只加载一个模型。
- 已保留中文网页、原始英文网页资源，以及声音设计、克隆、演绎和声音库页面。
- 已保留 `voices` 中的 4 个保存声音，包含 `zh_student_bright_01` 和 `zh_female_lively_01`，以及原有参考音频、文字稿和原始录音。
- `.breeze` 是同一 C++ 实现的参考编码缓存，需在 Mac 实测加载和生成。若某个缓存不兼容，可在声音克隆页面用 `voice-references` 或 `录音` 中的原始音频和准确文字稿重新保存声音。
- 声音库备注用于辨认声线，演绎要求用于控制生成。修改演绎要求后要重新点击生成，已经播放或生成的音频不会随输入文字改变。

## 包内环境与编译

`installers` 包含 Apple Silicon 独立 Python 与官方 CMake 归档；它们在 Mac 上解压，以保留符号链接和执行权限。无需安装 Python、pip、PyTorch、CUDA 或 Git，不写入系统 PATH。

`source/Breeze-TTS-2.cpp` 包含固定版本上游源码及其锁定的 ggml、shine 子模块。编译产物位于 `runtime/breeze-metal` 和 `runtime/breeze-cpu`；ggml/shine 使用静态链接，Metal 源码嵌入程序，启动不依赖 Homebrew 的动态库。底层版本及归档来源、SHA256 见 `DEPENDENCIES.md` 和 `installers/dependencies.json`。

部署缓存按源码/工具目录、脚本、编译器和后端区分；重新运行会复用符合记录的构建。失败日志和构建缓存保留，模型和声音文件不删除。把已编译目录移动后，应重新运行部署，让构建路径与当前目录保持一致。

## 排查

- `logs/deploy-*.log`：离线依赖解包、环境检查、CMake 配置与编译输出。
- `logs/mac-self-test.json`、`logs/diagnostics.json` 和服务/模型切换日志：加载或生成失败时先保留这些文件。
- 部署遇到 Apple 许可提示或 Xcode 首次配置要求时，请在 Apple 系统界面自行完成；脚本不代替你接受许可。
- Metal 不可用时，先用 `Start-CPU.command` 判断模型及声音库是否能正常运行。CPU 较慢，自测可能需要较长时间，不要重复启动多份任务。
- 页面仅绑定本机地址。生成保护覆盖本包网页及页面代理的 HTTP 请求；外部程序直接连接后端 WebSocket 时需自行协调。
